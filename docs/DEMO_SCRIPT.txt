ACADEMIC REGISTRATION PORTAL — DEMO SCRIPT
Wail Mohammed and Yesenia Ruiz | Team: YW-RegSytems
Target: 6 minutes 10 seconds. Maximum allowed: 7 minutes.

BEFORE RECORDING
1. Start the app and open http://localhost:8002/ in Chrome.
2. Open MySQL Workbench using the app's local database connection.
   Keep passwords and .env off screen. Prepare the two SELECT queries below.
3. Use new demo records so existing team data stays unchanged:
   Student: Taylor Demo, taylor.demo.01@example.edu, Computer Science.
   Course: DEMO 900, Computer Science, Registration Demo, 3 credits.
   Update: Registration Demo Updated, 4 credits.
4. Check that the email/code are unused. If already present, use .02 and
   DEMO 901 instead, including in your prepared SQL queries.
5. Keep this script beside the recording window. Practice once with a timer.

0:00–0:25 | INTRODUCTION
Click/do:
  Show the application and its name.
Say:
  "This is Academic Registration Portal, our college course-registration
  application. Angular provides the interface, Express handles requests,
  and local MySQL stores the records. It follows our database-class design."

0:25–1:10 | SEARCH AND JOIN
Click/do:
  Open Sections. Enter Database in Search. Select Fall 2026 and
  Computer Science, then click Search. Open the Database Systems Roster.
  Show its students and registration details, then click Close.
Say:
  "These filters run in SQL. The section results combine course, term,
  department, and instructor information. The roster joins student records
  with registrations for the selected section."

1:10–2:00 | INSERT A STUDENT
Click/do:
  Students → Add student.
  Enter Taylor, Demo, taylor.demo.01@example.edu, and Computer Science.
  Click Add student. Search for the exact email and show the saved row.
Say:
  "I am adding a new student. The form and server validate the values.
  MySQL creates the student ID and saves the record."

2:00–3:00 | INSERT AND UPDATE A SECOND TABLE
Click/do:
  Course catalog → Add course.
  Enter DEMO 900, Computer Science, Registration Demo, and 3 credits.
  Click Add course. Search for DEMO 900.
  Click its pencil icon. Change the title to Registration Demo Updated
  and credits to 4. Click Save course.
Say:
  "This inserts a course in a second table. I then select that course and
  update its title and credits. The UPDATE targets its primary key."

3:00–3:40 | VALIDATION AND CANCEL
Click/do:
  Students → Add student. Submit the empty form to show required fields.
  Enter valid names and the same demo email. Submit to show the duplicate
  error. Click Cancel and return to the saved student row.
Say:
  "Missing required values are rejected. A duplicate email is also rejected
  by the database's unique constraint, and the app shows a clear message.
  Cancel closes an unfinished form without saving another record."

3:40–4:20 | GROUPED REPORT
Click/do:
  Open Reports, select Fall 2026, and click Search.
  Show the enrolled, completed, occupied, and available-seat columns.
Say:
  "This report uses GROUP BY and aggregate functions in SQL. It helps the
  registrar compare enrollment and available seats by section. Completed
  and enrolled registrations occupy seats under our stated design rules."

4:20–5:40 | SHOW PERSISTENCE IN THE BROWSER AND MYSQL
Click/do:
  Reload the browser. Find the student and updated course again.
  Switch to MySQL Workbench. Execute the two prepared SELECT statements.
  Show the result rows, especially the updated course title and 4 credits.
Say:
  "The records remain after reloading. These direct MySQL queries show the
  same saved values, including the course update. The changes are stored
  in the database rather than only in the browser."

Prepared read-only queries:

  SELECT student_id, first_name, last_name, email, major
  FROM college_registration.students
  WHERE email = 'taylor.demo.01@example.edu';

  SELECT course_id, course_code, title, credits
  FROM college_registration.courses
  WHERE course_code = 'DEMO 900';

5:40–6:10 | DESIGN AND CLOSING
Click/do:
  Briefly show the updated ER diagram and report. State the OS and browser
  actually used for this recording.
Say:
  "Our schema separates catalog courses from term-specific sections.
  Registrations connect students and sections. The revised diagram uses
  consistent relationship constraints. The report includes the schema,
  functional dependencies, 3NF explanation, SQL queries, and testing."
