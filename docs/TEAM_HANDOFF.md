# YW-RegSytems: teammate handoff

This is the database-class implementation for Wail Mohammed and Yesenia Ruiz. The current frontend uses Angular 22 + TypeScript 6. The backend is Node.js/Express + local MySQL. The class's original ten-entity schema is the source of truth.

## Start here

1. Clone `https://github.com/Wail-Mohammed/YW-RegSytems.git`.
2. Install Node.js 24.15+ in the 24.x series and MySQL. Run `npm ci` in the clone.
3. Copy `.env.example` to `.env`; enter your own local MySQL connection.
4. Run `npm run db:setup`, then `npm start`; open http://localhost:3000/.
5. A separate local MySQL helper is available through `npm run local:setup` and `npm run local:start`; read the README before using it.

Every developer supplies their own password. Git contains configuration examples and SQL scripts, not Wail's local credentials or database files. Normal browser operations do not require writing SQL.

## Find and change the right layer

| Task | Files |
|---|---|
| Screens, navigation, filter state | client/src/app/app.component.ts and .html |
| Add/edit and confirmation dialogs | client/src/app/record-dialog.component.ts and .html |
| Typed API data and HTTP calls | client/src/app/models.ts and api.service.ts |
| Layout and narrow-screen styling | client/src/styles.css |
| Routes, API responses, HTTP errors | index.js |
| SQL and registration transactions | Repository.js |
| MySQL connection/UTC handling | DAO.js and config.js |
| Backend field validation | validation.js |
| Entities, attributes, keys, constraints | sql/schema.sql; docs/PROJECT_REQUIREMENTS.md |
| Sample records and demonstration IDs | sql/seed.sql and sql/schema-notes.txt |
| ER/cardinality explanation | docs/RELATIONSHIPS.md and er-diagram.mmd/.svg |
| Report text and rendering | scripts/build-report-content.py and generate-report.js |

Do not edit `dist/` to change the interface; it is generated by `npm run build` and is not committed. API endpoints stay under `/api`. SQL filtering, joining, grouping, and modification belong on the server. Preserve the original unique pairs and the ten entity relationships when making changes; document any design revision.

## Work without overwriting each other

Keep main runnable. Create a branch, make a focused change, run the relevant checks, push that branch, and open a pull request. Include schema changes and documentation in the same review when they depend on each other. Avoid rewriting shared Git history.

The baseline before the Angular conversion is tagged `baseline-vanilla-frontend`. It is a recovery/reference point, not the current frontend source.

## Verification

- `npm test`: backend validation.
- `npm run check`: JavaScript syntax plus strict TypeScript checking.
- `npm run build`: production Angular build, including strict template checks.
- `npm run test:integration`: real MySQL transactions and persistence in a disposable database.
- `npm run test:browser`: real Chrome against the Angular build and a disposable MySQL database.

Run the build before browser checks. The MySQL test account needs CREATE/DROP DATABASE permission for disposable fixtures. Recorded results are in docs/verification.json; browser scenarios and screenshots are under docs/. A changed application should be retested before replacing those records.

## Remaining work for submission

- Record/upload a viewable demo of at most seven minutes using docs/DEMO_SCRIPT.txt.
- Confirm the report team ID/filename and add the demo URL in docs/submission.json.
- Run `npm run report` and check the resulting PDF and README video link.
- Test on a real iPhone or Android and document the device/browser before claiming mobile extra credit. Narrow-viewport emulation alone is not that evidence.
- Review the application and be able to explain the schema, queries, framework role, and transaction rules.

The public repository can be viewed and cloned by your teammate. Wail handles any collaborator invitations needed for write access.
